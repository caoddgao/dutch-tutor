## 0. 分工与规矩

### 0.1 谁做什么

| 角色 | 在哪 | 做什么 |
|---|---|---|
| **用户** | — | 拍板；在每个试用点安装试用、提意见；最后用录音模式录真人音频 |
| **云端施工会话**（Claude Code on the web） | GitHub 仓库 | 写代码、写我们自己的内容、测试，自己合并 |
| **审核 / 设计会话**（claude.ai 聊天） | — | 设计讨论、审核每个阶段的结果、给施工会话写任务 |
| **DS**（DeepSeek，在用户电脑上） | `F:\Working_Projects\Dutch_Tutor_v2\NN_Pack` | 整理 Naar Nederland 资料包（见 `04_DS_NN_PACK.md`），不碰仓库 |
| **GitHub Actions** | 云端 | 每次提交跑测试和内容校验；合并到 `main` 后打 Windows 安装包；生成我们自己内容的合成音 |

### 0.2 施工会话的规矩（写进仓库的 `CLAUDE.md`）

1. 开工先读 `docs/STATUS.md`（≤ 100 行：当前阶段、已完成、下一步、已知问题），收工时更新它。不另写报告文件。
2. 每个任务在一个分支上做 → 开 Pull Request → **CI 全绿后自己合并**到 `main`。不 force push，不改历史。
3. **不降低检查标准来求通过**，不为了通过而改测试。
4. 设计说明是合同。实现中发现设计行不通，在 `STATUS.md` 的"待决问题"里写清楚，停下来等决定，不擅自改设计。
5. 密钥只放在 GitHub Secrets（`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`）和用户本机，绝不写进代码、日志或提交。
6. **Naar Nederland 的课文、练习、录音不进仓库。** 仓库里只放 `nn-index.json`（目录摘要）和一个用于测试的**假资料包**（内容是我们自己编的，格式与真资料包一致）。
7. 界面以效果图为准。新页面先做成静态页面给用户看，再接功能。

### 0.3 试用点

用户只需要在三个时间点上场：**T1**（阶段 2 结束）、**T2**（阶段 4 前半）、**T3**（阶段 5 结束，正式版）。每次从 GitHub Releases 下载安装包，装上直接用。审核会话会把下载地址和"这次看什么"整理好给用户。

## 阶段 1 · 骨架（约 2–3 个施工会话）

**目标**：能安装、能打开的空壳程序，界面和效果图一致，打包流程跑通。

任务：

1. 建立 Tauri 2 + React + TS + Vite 项目；`CLAUDE.md`、`docs/STATUS.md`。
2. 设计规范：颜色、字号、间距、圆角、阴影，浅色和深色两套主题（CSS 变量）；字体打包进程序；字号缩放系统（荷 / 中 / 英三个比例）。
3. 应用外壳：侧栏导航、顶栏（含英文开关）、页面路由，各页先放空状态；窗口变窄时侧栏收起。
4. 本地存储：SQLite 建表（进度、复习、录音、反馈、设置）+ 迁移机制。
5. 设置页：主题、字号、英文开关、播放速度，可用并能保存。
6. CI：每次提交跑类型检查、单元测试；合并到 `main` 后打 NSIS 安装包，发到 GitHub Releases（预发布）。

**验收**：
- 安装包能在 Windows 11 上安装和打开，开始菜单里有图标。
- 浅色 / 深色 / 跟随系统切换正常；字号滑块即时生效。
- 首页和课程地图的静态版和效果图一致（课程地图里的课先用假数据）。

## 阶段 2 · 学习引擎（约 3–4 个施工会话）→ 试用点 T1

**目标**：用样板内容完整走一遍"上课 → 练习 → 复习"。

任务：

1. 内容数据格式（`content/` 结构、JSON Schema）和内容校验脚本（`01_DESIGN.md` §11 的规则 1–7）；校验进 CI。
2. 资料包读取层：按 `03_PACK_FORMAT.md` 读取；导入流程（选文件夹 → 校验格式版本 → 复制到程序数据目录）；用假资料包测试。
3. 音频层：按 §5.1 的优先级找音源；播放、0.75 倍慢放；录音跟读、原声对比、双声波显示。
4. 上课页：§3 的六步流程；句卡、点词看词条、词卡、小贴士、本课进度和断点续学。
5. 练习：E1–E4、E7、E8 先做；E5、E6 先做"录音 + 参考答案 + 自评"版。
6. 复习：R1–R3、间隔安排、今日复习、按课复习、错题集中练。
7. 课程地图接真实数据：状态（未学 / 学过 / 掌握）、推荐下一课、不锁课。
8. 样板内容：发音入门 P01、P02（我们自己写）+ 假资料包里的 1 课正课。如果 DS 试点已完成，T1 时用户可以导入真资料包，试第 21–23 课。

**T1 用户看什么**：上课流程顺不顺、句卡和字号是否合适、复习三种方式好不好用、原版录音的切分是否准确。T1 的意见改完再进阶段 3。

## 阶段 3 · 资料包全面接入与课程编排（约 2 个施工会话）

**目标**：真资料包导入后，全部正课的骨架都能打开。

任务：

1. `nn-index.json` 进仓库；`course.json` 编排全部正课，包括拆分课（按 §2.1 的规则，由 `nn-index.json` 的统计自动算出建议，审核会话确认）。
2. 正课运行时合并：编排 + 资料包句子 / 词 / 练习；资料包里标记为"跳过"的练习不显示。
3. 词典合并：NN 词表 + `words/own.json`；词形 → lemma 的映射（`woont` → `wonen`）。
4. 资料包缺失或版本不符时的提示；重新导入。
5. 内容校验的完整模式（`--pack`）可以在用户电脑上运行，输出报告。

**验收**：用真资料包，第 21–65 课都能进入、播放、点词；完整校验报告里没有"引用找不到"一类的错误。

## 阶段 4 · 内容（约 4–6 个施工会话，分批）→ 试用点 T2

**目标**：A1 的全部内容写完。

批次（每批完成后跑校验；第 2 批完成后进行 T2）：

| 批 | 内容 |
|---|---|
| 1 | 发音入门 P03–P10（音组按 NN 第 1–13、20 课排）；功能词白名单 |
| 2 | 小贴士 G01–G08；正课第 21–30 课的"我们这一半"：补充短句、E5/E6 题、练习编排、小贴士挂载 |
| 3 | 第 31–45 课 + G09–G12 |
| 4 | 第 46–55 课 + G13–G16 |
| 5 | 第 56–65 课 |
| 6 | 合成音：GitHub Actions 为我们自己的内容生成 Azure 音频（每 3.2 秒 1 次，带缓存）；资料包里需要合成的部分由 DS 在本机生成 |

**T2 用户看什么**：第 21–30 课实际学一周，重点看补充内容的难度、小贴士是否看得懂、练习量是否合适。根据意见调整后续批次。

## 阶段 5 · 收尾（约 2–3 个施工会话）→ 试用点 T3（A1 正式版）

任务：

1. 录音模式（§5.5）：逐句录、回放、保存替换、只看未录、标记不自然、导出 / 导入。
2. Azure 发音评分（§5.4）：设置里填密钥、测试连接、E5/E6/R3 显示评分、本月用量。
3. 阶段测验 1–3（来自资料包）+ 结业模拟考（我们出题：口语"问答"约 10 题 + "补全句子"约 12 题；阅读"技术性阅读"约 10 题 + "功能性阅读"约 5 篇各 2 题），并给出官方在线模拟考的链接。
4. 学习数据备份与恢复；内容报错的导出。
5. 打磨：动效、空状态、错误提示、性能（冷启动 < 3 秒）；去掉一切开发者视角的文字。
6. 正式版安装包 v1.0.0。

**验收（T3）**：用户从安装、导入资料包到学完任意一课、做复习、做模拟考，全程不需要技术帮助。

## 附：预计工作量

- 施工会话：合计约 13–18 个。每个会话做一个边界清楚的任务，结束时合并并更新 `STATUS.md`。
- DS 资料包：试点约 1 个工作段，全量约 2–3 个工作段（主要时间在人工抽查对齐质量）。
- 用户：三个试用点，每次半小时到一周不等（T2 需要实际学一段时间）。
